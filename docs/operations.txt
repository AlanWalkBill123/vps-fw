VPS-FW v3.1.8 — 确认超时恢复版
日期：2026-11-16

此版按你的偏好取舍：发生已检测到的故障时宁可阻断网络，使用商家的 VNC 控制台恢复。
v3.1.8 仅对正常确认超时恢复上一次已确认配置；其他故障保持隔离。

安装与首次使用
  sudo bash vps-fw.sh
  fw
建议首次安装和迁移都从 VNC 操作。先应用并确认防火墙，再启动交易程序。
向导中的 SSH 端口只是探测建议，请用 ss -lntp 核对，尤其是 systemd socket activation。
默认有当前 SSH 来源时只允许该 IP；动态地址变化可能锁住自己，也可以明确选择 ANY。
常规规则更新会短暂隔离网络再原子装载新规则，可能影响正在运行的连接/交易请求。
不要在交易关键时段更改规则。

应用与确认
菜单 [6] -> [1] 应用后，须在 300 秒内用新连接验证，再执行 fw confirm。
超过期限时，审计计时器在完整性检查通过后恢复上一次已确认的完整配置。
首次安装无已确认版本、恢复失败或其他异常时才安装隔离表，阻断非回环网络。
连续应用但未确认，不覆盖已确认基线。倒计时通过每约 5 秒的检查判定，并非精确到毫秒。
未确认时重启也会隔离。不会自动放开公网，不会删除配置来“救 SSH”。
菜单 [6] -> [2] 可显式永久应用；这只跳过确认倒计时，完整性检查仍然运行。
存在待确认配置时菜单 [6] 的编号不同，会显示确认、隔离和重新应用草稿。

主要修复
1. 取消把普通 DROP 规则提到 SSH 白名单之前的机制。普通规则保持顺序。
   专用 SSH 白名单是公网 SSH 新连接的来源上限；允许范围内仍会执行普通规则。
   菜单 [4] -> [11] 设置独立 SSH 黑名单，需要明确地址；它优先于普通 SSH 放行。
   如果普通规则前面已经 ACCEPT，后面的普通 DROP 不会反过来推翻它；可调整顺序。
2. 进入预设或切换 Ping 不再改 SSH_PORT；只有首次向导和 [4] -> [12] 显式修改端口。
3. 公网与信任接口双向互斥，生成规则时再次校验；容器前缀快捷规则排除 WAN。
   排除同时作用于入站和出站，避免 WAN=br-public 等名字绕过过滤。
4. 修复容器桥接 IPv6 邻居发现，严格出站模式仍保留必要的桥接 NS/NA（hoplimit 255）。
5. 新版本配置、规则数据库与编译规则保存为独立目录，带 SHA256 清单；current 原子切换。
   缺失、截断、哈希错误或 nft -c 失败都不会被当作可用版本。
6. 加锁、生成、写文件和系统服务配置失败会返回失败；确认不会接受损坏版本。
   预览失败不会展示半截输出；菜单写入失败不会谎报成功。
7. 开机先由 systemd 单元中的独立 nft 命令隔离，再校验并加载已确认版本。
   主脚本或配置缺失时仍有隔离兜底；审计程序无法执行也会触发独立隔离服务。

业务服务依赖
已安装的 docker.service / containerd.service 会在应用时自动添加防火墙启动依赖。
你的交易程序必须作为 systemd 系统服务运行，并显式绑定，例如：
  sudo fw bind-service trading.service
这不会立即重启业务。绑定后，其下次启动必须等待防火墙服务成功，且 fw health 通过。
待确认、隔离或配置损坏时，业务启动检查失败。
业务以非 root 用户运行时，单元中的“+”前缀让健康检查以管理员权限读取配置。
业务若自行设置 RootDirectory/RootImage 等文件系统隔离，必须另外确认检查程序可见；
看不到程序会阻止业务启动，不会跳过检查。
Docker 之后才安装时，手动执行：
  sudo fw bind-service docker.service
  sudo fw bind-service containerd.service
绑定只控制启动；运行中的业务发生故障时由隔离规则断网，不自动杀掉业务进程。

VNC 恢复
A. 配置完整、无待确认修改，仅因异常被隔离：
     sudo fw restore
   校验失败则继续隔离。修复原因并恢复网络后，手动启动被挡住的业务服务。
B. 倒计时超时或还有 pending.state：
     sudo fw
   核对/修改草稿，菜单 [6] -> [3] 重新应用，然后在新倒计时内确认。
C. 当前配置损坏：
   面板 [8] -> [1] 可将校验通过的历史版本导入草稿，再应用。
   若当前配置损坏导致面板无法打开，从 VNC 执行：
     sudo fw generations
     sudo fw recover 上面列出的24位版本ID
   所选版本必须通过完整性校验；成功后开启新的确认倒计时，还需 fw confirm。
   先备份 /etc/vps-fw 并核对选中的历史策略。不要用 nft flush ruleset 当作恢复步骤。
D. 主程序文件缺失：
   从 VNC 放回已核验的 vps-fw.sh 到 /usr/local/sbin/vps-fw（权限 755），
   再按 A/B/C 处理。
“fw rollback”和“fw emergency-off”现在均为立即隔离的兼容命令，不再撤掉保护。
“fw uninstall”拒绝自动卸载。如需退役，先从 VNC 停止所有业务，安排替代防护，
再人工清理 vps-fw* 服务/计时器、业务的 50-vps-fw.conf drop-in 和本程序的两张 inet 表。

迁移旧版
升级前备份当前配置，在测试 VPS 验证后再部署。
旧版仍有待确认修改时，安装器拒绝替换不同内容的程序。
先在 VNC 核对旧版状态并完成旧版确认，再安装新版。不要依赖旧版超时回滚维持保护。
新程序第一次应用后会生成 generations；旧的平铺文件保留，但不作为新版自动恢复依据。
相同内容的脚本可在待确认期间重新打开面板。
升级时需要重新应用草稿，才能写入新版启动服务；仅复制脚本不等于迁移完成。

适用范围与限制
已测试环境为 Debian 13 ARM64、systemd、nftables 1.1.3、常规 Docker bridge。
不宣称 Debian 11/12、Ubuntu、其他 nft/Docker 版本或 AMD64 实机已验证。
只配置一个 WAN。多公网接口、VRF、macvlan/ipvlan、host network、Swarm、Kubernetes、
自定义容器桥名、VPN 出口/子网路由必须另行设计与验证。
TRUSTED_IFS 是对宿主机入站的完全信任，不是转发授权；不要把公网接口设成“内网”。
WireGuard/Tailscale 访问宿主机可用不代表它们能转发到容器或作为出口节点。
容器之间默认允许同类桥接互访，但最终还可能受 Docker 自己的隔离规则限制。
普通策略优先保留 established/related；普通规则和 SSH 黑名单针对新连接。
要立即切断已有连接用 fw lockdown；它会同时切断全部非回环网络。
默认出站允许；菜单提供出站 DROP 及 DNS/NTP/HTTP(S) 预设，但它不是按交易所域名过滤。
需要结合实际交易所 API/WebSocket、DNS、NTP、IPv6 地址和日志进行放行与实测。

安全边界
这不是云厂商上游安全组，无法防住占满 VPS 线路的流量攻击。
SHA256 清单用于发现损坏与意外改动，不是对已取得 root 权限者的信任边界。
有 root 权限的程序仍可停用服务、改清单、删除规则；内核或 nft 本身不可用也无法保证阻断。
审计是周期性检测；外部执行 flush ruleset 可能在检测前造成短暂暴露。
因此不要并行运行会全量重写规则集的其他防火墙，不允许不可信容器拥有宿主机 NET_ADMIN。
业务启动依赖能阻止已绑定业务在防火墙启动失败时启动，但不自动覆盖系统里每一个服务。
测试通过不代表“任何情况下都安全”，也不能代替交易 API 权限限制及主机补丁管理。


3.1.1 升级与出站规则
安装前使用新版校验当前保存配置；不兼容时拒绝替换旧程序。已有 /064、/010 等前缀必须
先在旧版改成预期的十进制值，重新应用并确认。不要手动修改 manifest 来绕过验证。
安装后重新应用并确认，才能更新生成规则和 systemd 单元。
宿主机出站规则现在匹配所有接口，目的 CIDR 仍由规则指定。严格出站默认不放行容器桥
和信任接口上的新连接；访问容器/私网时手动添加出站 HOST 规则，明确目的 CIDR 和端口。
已建立连接、回环和必要的控制报文保留内置例外。TRUSTED_IFS 的入站语义不变。

审计锁与恢复并发
审计定时服务使用 watch 子命令。应用锁忙时退出 75，systemd 视为正常，随后重试。
从首次观察到忙起持续达到 120 秒（或计时异常）会触发独立隔离；正常审计超时仍为 20 秒。
独立隔离尝试写入 fault.state，即使标记不可写仍执行 nft 隔离；与解除隔离共用 /run/vps-fw-guard.lock，避免恢复把新故障抹掉。
解除隔离还要求独立守护单元已结束且未失败，不能只依赖标记文件。
本次恢复中又发生故障会拒绝解除隔离。核对故障后，从商家控制台重新启动恢复事务。
不要手工删除标记或隔离表。短锁获取失败、内核不可用或磁盘不可写仍需控制台排障。
交互终端执行 lockdown/rollback/emergency-off 要输入 YES；--yes 或非交互调用直接执行。
